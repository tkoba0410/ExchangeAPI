# Contracts Overview

## 1. Purpose

本書は、本ライブラリにおける **利用者向け契約（User-facing Contract）** の正本である。

本書は、

* 取引所仕様に起因しない差異を排除し、
* 利用者が分岐を書かずに利用できる範囲を明確化する

ことのみを目的とする。

型定義、実装方法、背景説明は本書の対象外とする。

---

## 2. Scope

本書が規定するのは以下に限定される。

* 利用者が **必ず同一の振る舞いを期待してよい領域**（Guaranteed）
* 取引所仕様により **差異が生じ得ることを利用者が許容する領域**（Allowed Variations）

本書は、取引所固有仕様の詳細、実装手法、最適化方針を規定しない。

---

## 3. Guaranteed（差異禁止）

本節に記載された事項については、**取引所間で差異が存在してはならない**。
利用者は、以下について分岐や例外処理を書く必要がない。

### 3.1 API 呼び出し前提条件

* 同名の Contracts API は、取引所間で **前提条件の差異を持たない**
* 取引所固有の追加前提条件（例: accountId 等）は、

  * Composition により自動的に満たされるか、
  * 別 API として明示的に分離されなければならない

---

### 3.2 戻り値・エラー表現

* Contracts API の戻り値は常に `Call<TRequest, TResponse>` である
* `NotSupported` は capability 不足を示す場合にのみ使用される
* `NotSupported` を制御フローとして利用することは禁止される

---

### 3.3 意味論の統一

以下の概念の意味論は、取引所に依存せず常に共通である。

* Symbol / Market
* OrderKey
* Side / OrderType / TimeInForce
* Page / Limit / Cursor

取引所 API における表記差は、利用者に露出してはならない。

---

## 4. Allowed Variations（差異許容）

本節に記載された事項については、取引所仕様により差異が存在し得る。
利用者は、必要に応じて capability 等を用いて分岐する。

### 4.1 機能の有無

* 取引所によって提供されない機能が存在し得る
* 利用可否は capability により事前に判定可能でなければならない

---

### 4.2 制約値・仕様差

以下は取引所仕様に依存する。

* 最小数量・数量精度
* 価格精度
* レート制限
* メンテナンス時間

---

## 5. Prohibitions

以下を明示的に禁止する。

* 取引所差異を理由とした API 呼び出し前の try/catch 分岐
* `NotSupported` を利用した通常制御フロー
* 取引所固有表記（文字列）を利用者 API に露出すること

---

## 6. Non-Goals

本書は以下を目的としない。

* 実装方法の最適解提示
* 設計選択の理由説明
* 取引所仕様の網羅的記述
