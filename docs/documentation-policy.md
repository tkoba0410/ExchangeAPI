# Documentation Policy

## 1. Purpose

本ドキュメントは、ExchangeAPI プロジェクトにおける  
**文書化の範囲・粒度・配置・更新ルールを固定し、  
「文書をどう書くべきか」での揺れや迷いを防ぐ**ことを目的とする。

本リポジトリにおける文書は、情報共有や網羅性のためではなく、  
**設計判断・境界・合意点を固定するため**にのみ存在する。

---

## 2. Scope

本ポリシーが対象とするのは、以下の文書である。

- 設計原則・構造・境界に関する文書
- 公開契約（Contracts / Interfaces）
- API インベントリ（API一覧）
- チェックリスト
- 例外（意図的な逸脱）の記録

以下は **本ポリシーの対象外**とする。

- API仕様本文（公式ドキュメントを正本とする）
- CI / 自動化ツールの説明
- テスト仕様書・テスト手順書
- 実装手順書・チュートリアル
- サンプルコード集

※ API仕様本文は、公式ドキュメントを正本とし、本リポジトリでは再記述しない。

---

## 3. Placement Rules

- `README.md` 以外の文書は、すべて `docs/` 配下に配置する
- ルートディレクトリに新たな設計・運用文書を追加しない
- `docs/` 配下の文書は、相対リンクのみを使用する

`README.md` は **入口（ナビゲーション）専用**とし、  
設計原則・契約・API一覧等の本文を記載しない。

---

## 4. Document Types and Responsibilities

本リポジトリで管理する文書の種類は、以下に限定する。

### 4.1 Design Principles
- 位置: `docs/topspec/guide.md`
- 役割: 覆さない設計原則・判断理由（Why）

### 4.2 Structural Overview
- 位置: `docs/topspec/core.md`
- 役割: 全体構造・層構成の要約（Where / What）

### 4.3 Contracts and Boundaries
- 位置: `docs/contracts/`
- 役割: 公開境界、DTO形状、命名規約、共通契約

### 4.4 API Inventory
- 位置: `docs/inventory/`
- 役割: 使用しているAPIの一覧（棚卸し）
- 注意: API仕様の再記述は行わない

### 4.5 Checklists
- 位置: `docs/checklists/`
- 役割: 追加・変更・レビュー時の判断基準

### 4.6 Exceptions
- 位置: `docs/exceptions.md`
- 役割: 意図的な原則逸脱の記録と理由の明文化

### 4.7 Documentation Policy
- 位置: 本書
- 役割: 文書化そのものの判断基準

---

## 5. What to Write / What Not to Write

### 書いてよいこと

- 設計判断の理由
- 層や責務の境界定義
- 公開契約・形状ルール
- APIの存在一覧（method / path / 参照元）
- 判断を助けるチェック観点
- 意図的な例外とその理由

### 書いてはいけないこと

- APIリクエスト／レスポンスの詳細仕様
- 公式ドキュメントの内容の転記
- 実装手順・コード解説
- テストの書き方・実行手順
- 「現時点では〜」といった未確定メモ（判断を固定できないため）

---

## 6. Update Rules

文書は以下の場合にのみ更新する。

- 設計原則が変わった場合  
  → `docs/topspec/guide.md`

- 層の責務や公開境界が変わった場合  
  → `docs/contracts/`

- APIを追加・削除・差し替えた場合  
  → `docs/inventory/`

- 例外的な実装・判断を行った場合  
  → `docs/exceptions.md`

- PRを作成する場合  
  → `docs/checklists/review.md` を自己確認する

---

## 7. Anti-Rules (When Not to Document)

以下の場合、文書は追加しない。

- 一時的な実装都合である
- 近いうちに削除・置換予定である
- CIや自動化によって担保されている
- 公式ドキュメントを参照すれば足りる
- 判断や合意を固定する必要がない

**迷った場合は「書かない」を選ぶ。**

---

## 8. Authority

本ポリシーは、`docs/` 配下のすべての文書に優先する。

コード実装は、本ポリシーに基づいて作成・修正されるものとする。

文書構成や粒度に迷いが生じた場合は、
本ポリシーに立ち返って判断すること。
