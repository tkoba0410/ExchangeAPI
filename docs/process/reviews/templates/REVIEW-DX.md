## 2. 観点詳細

### 自然な利用形態

* 判定基準: 利用者が最短経路で正しい呼び出しに到達できる
* OK条件: 主要ユースケースが直感的APIで完結し、不要な前提知識を要求しない
* NG条件: 正常利用に過剰な手順や内部事情の理解を必要とする
* 不合格例: 単純な取得処理でも複数層の内部型を利用者が組み立てる必要がある
* 該当Fatal: 原則なし（公開契約破壊に波及する場合は F3）
* 修正方針: 公開面をユースケース単位で再整理し、利用導線を単純化する

### 誤用耐性

* 判定基準: 想定しやすい誤用が型/契約/ガードで抑止される
* OK条件: 誤った引数・順序・状態に対し、早期に検出・拒否できる
* NG条件: 誤用が静かに通過し、実行時の遅延障害として顕在化する
* 不合格例: 必須値欠落を許容して下流で null 例外になる
* 該当Fatal: 原則なし（Security/Reliability 重大欠陥に波及する場合は F4/F5）
* 修正方針: 境界バリデーションを追加し、誤用をコンパイル時または入口で遮断する

### 診断可能性

* 判定基準: 失敗時に次行動を決められる診断情報が残る
* OK条件: エラー分類・文脈情報・再試行可否が一貫して提示される
* NG条件: 失敗理由が曖昧で、調査に実装読解を要する
* 不合格例: 例外が汎用メッセージのみで endpoint/context を欠く
* 該当Fatal: F5（再現/復旧不能な信頼性欠陥に波及する場合）
* 修正方針: エラー分類と観測項目を標準化し、最小限の診断文脈を付与する

### secret非露出

* 判定基準: secretがログ/例外に出ない
* OK条件: secret/署名素材がログ・例外・監視イベントで常にマスクされる
* NG条件: secretまたはその断片が出力経路のどこかで露出する
* 不合格例: 例外メッセージに API Key 断片を含む
* 該当Fatal: F4（Security重大違反）
* 修正方針: 出力境界で機密項目を一律マスクし、禁止パターン検査を導入する
