# ExchangeAPI v2.0.0 Release Note

## Purpose

GitHub Release または配布告知にそのまま転用できる `ExchangeAPI v2.0.0` の要約を置く。

## Summary

`ExchangeAPI v2.0.0` は、外部利用者が直接触れる naming と error observation を中心に整理した breaking release である。  
一方で、scalar 基本契約、`CallError.Kind` taxonomy、test taxonomy、CLI/MCP の surface そのものは大きく作り替えない。

この release で主に変わるのは次の点である。

- `Call<TRequest, TResponse>` が `CallResult<TRequest, TResponse>` へ変わる
- facade public method が `*CallAsync(...)` から `*Async(...)` へ変わる
- client 生成 method が `Create*Client(...)` から `Create*ClientBundle(...)` へ変わる
- `CallError` に `HttpStatusCode`, `VenueErrorCode`, `VenueErrorMessage` が追加される
- CLI と MCP は上記 detail を verbose / structured details で扱えるようになる
- human-facing な時刻表示は local with offset 優先へ寄せる
- private credentials は core 正本から storage / encryption recipe を外し、auth provider 契約へ責務を寄せる
- auth provider の具体 shape は `IApiCredentialProvider.OpenSessionAsync(...)` 型を採用する
- provider 実装は `ExchangeApi.Optional.Credentials` package として分離される
- credential failure は typed に分類され、CLI / MCP が利用者向け通知へ写像する
- MCP は read-only 情報取得を広げ、state-changing operation は扱わない
- live / manual verification は endpoint ごとに `safe/tolerable/dangerous` で分類する
- verification evidence は `local/evidence/` に集約する
- library / optional は NuGet package、CLI / MCP は executable artifact として配布する

## Adopted Breaking Changes

- result container naming
  - `Call<TRequest, TResponse>` -> `CallResult<TRequest, TResponse>`
- facade method naming
  - `GetTickerCallAsync(...)` -> `GetTickerAsync(...)`
- factory method naming
  - `CreateProtocolClient(...)` -> `CreateProtocolClientBundle(...)`
  - `CreateNativeClient(...)` -> `CreateNativeClientBundle(...)`
- error observation detail
  - `CallError.HttpStatusCode?`
  - `CallError.VenueErrorCode?`
  - `CallError.VenueErrorMessage?`
- adapter exposure
  - CLI: `--verbose` 時に追加 detail を表示可能
  - MCP: `upstream_error.details` に追加 detail key を保持可能
- private credentials
  - core は auth provider 契約を持つ
  - storage / encryption recipe は CLI / guide / optional 実装へ外に出す
  - auth provider の具体 shape は `IApiCredentialProvider.OpenSessionAsync(...)` 型とする
  - session は `ApiKey` と `Sign(string payload)` を持つ
  - `ApiSecret` は public API に出さない
  - 通常利用では client / adapter 側が session を隠して扱ってよい
  - 明示 session overload は private endpoint にだけ追加する
  - 明示 session overload の引数順は `request`, `credentialSession`, `cancellationToken` とする
- optional credentials
  - `ExchangeApi.Optional.Credentials` を追加する
  - `PlainText` provider は sample / test / local dev 用であり、production 推奨ではない
  - `AgeFile` provider は復号処理を `IAgeCredentialFileDecryptor` に委譲する
  - `AgeFile` provider の復号後 JSON は `version`, `venue`, `apiKey`, `apiSecret` を required とする
- credential failure notification
  - failure は `ApiCredentialException.Kind` で分類される
  - CLI は stderr と exit code `2` へ写像する
  - MCP は private tool 非公開、または `account_unavailable` structured error へ写像する
  - detail key は `credentialErrorKind`, `venue`, `provider`, `reason` を使う
- MCP read-only surface
  - 注文、キャンセル、入金、出金は MCP tool にしない
  - private read endpoint は inspection read tool の候補にできる
- verification layout and risk model
  - API 契約分類は endpoint matrix に残す
  - live / manual verification は `safe/tolerable/dangerous` で endpoint ごとに判断する
  - evidence と local artifact は `local/evidence/` に寄せる

## Intentionally Unchanged

- `CallError` / `CallMeta` の型名
- `BitflyerClientFactory` / `BinanceClientFactory` の class 名
- endpoint `*Request` と `*ClientOptions`
- `CallError.Kind`
  - `Transport / Http / Codec / Semantic / Mapping`
- scalar 基本契約
  - quantity 系は `decimal`
  - timestamp は `DateTimeOffset`
  - parse は invariant culture
- enum / string vocabulary の境界
  - closed-set は venue-local enum
  - open-set は string
- unit / contract test taxonomy and source/test project layout
- CLI / MCP surface の 1:1 統一
- CLI canonical で API key / secret の直接引数入力を許可しない方針
- CLI / MCP の配布を NuGet package にしない方針

## Adapter Notes

- CLI は endpoint inspection / execution 導線としての shape を維持する
- MCP Server は bot-oriented tool surface を維持する
- ただし、error detail、timestamp、decimal string、`venue` / `symbol` などの基底語彙は adapter 間で整合させる
- CLI / log は human-facing な local with offset を優先し、MCP structured response は UTC / structured contract を維持する
- CLI の `v1.x` canonical では credentials input は age-backed source を正本としつつ、`v2.0.0` では core から `age` 固定の色を外す
- CLI / MCP executable は release asset として扱い、NuGet publish 対象にはしない

## Distribution Notes

- library package は NuGet / GitHub Packages の publish 対象である
- optional package も NuGet / GitHub Packages の publish 対象である
- `ExchangeApi.Optional.Credentials` は `v2.0.0` publish 対象に含める
- CLI executable `exchangeapi` は release asset として扱う
- MCP executable `exchangeapi-mcp` は release asset として扱う
- 生成物は `local/nuget/` または `local/publish/**` に生成し、git 管理しない

## Migration Pointers

- library 利用者は型名と method 名の rename 対応を先に行う
- private endpoint 利用者は credentials 直渡しを auth provider 注入へ移行する
- provider 実装が必要な利用者は `ExchangeApi.Optional.Credentials` を追加する
- CLI 利用者は verbose error detail の追加を確認する
- MCP 利用者は `upstream_error.details` の key 追加を確認する
- 詳細は [`docs/migration-v2.0.0.md`](../migration-v2.0.0.md) を参照する
- 設計理由は [`docs/breaking-changes-v2.0.0.md`](../breaking-changes-v2.0.0.md) を参照する
