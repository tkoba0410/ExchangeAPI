# Release Notes v3.0.0

## Highlights

- Consolidated each venue into one project and one package.
- `ExchangeApi.Exchanges.Bitflyer` is now the single bitFlyer venue package.
- `ExchangeApi.Exchanges.Binance` is now the single Binance venue package.
- `Protocol`, `Native`, `Composition`, and `Vocabulary` remain as folder, namespace, and test boundaries.
- Layer-specific venue packages and projects are removed.

## Compatibility

- Existing namespaces are preserved.
- Existing facade, factory, and endpoint public API names are preserved.
- `ExchangeApi.Primitives`, `ExchangeApi.Optional.Credentials`, and `ExchangeApi.Optional.Logging` remain separate packages.
- `Unified` is not implemented in v3.0.0.
- bitFlyer Realtime API is not included in v3.0.0 and is planned for v3.1.0 design discussion.

## Migration

- Consumers that referenced `ExchangeApi.Exchanges.Bitflyer.Composition` should reference `ExchangeApi.Exchanges.Bitflyer`.
- Consumers that referenced `ExchangeApi.Exchanges.Binance.Composition` should reference `ExchangeApi.Exchanges.Binance`.
- Source-level `using` directives for existing layer namespaces can remain unchanged after switching package references.

## Safety

- Layer-specific venue packages are not generated.
- Live tests skip safely without opt-in.
- No credentials, API keys, API secrets, signatures, or Authorization headers should appear in evidence, logs, results, exceptions, stdout, or stderr.
