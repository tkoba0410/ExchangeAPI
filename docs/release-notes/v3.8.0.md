# Release Notes v3.8.0

## Highlights

- Fixed v3.8.0 as a Realtime Foundation Inventory / Minimal Contract Hardening release.
- Clarified the relationship between DTO-only realtime streams and envelope realtime streams.
- Added `NonTargetMessageIgnored` as a realtime diagnostic event type.
- Made public and private bitFlyer envelope streams emit a diagnostic event for non-target / unknown channel messages.
- Added deterministic tests for non-target / unknown channel diagnostics.
- Classified v3 realtime foundation gaps for v3.9, v4, v5, and v6 handoff.
- Revised the post-v2 roadmap so v4 is the stable baseline / maintenance / release hardening stage.

## Compatibility

- Existing HTTP endpoint contracts are unchanged.
- Existing DTO-only realtime APIs are unchanged.
- Existing stream envelope APIs are unchanged.
- Existing optional credentials, logging, testing, and reactive APIs are unchanged.
- Core and venue packages still expose `IAsyncEnumerable<T>` as the primary realtime API.
- `System.Reactive` remains limited to `ExchangeApi.Optional.Reactive`.

## Realtime Contract Clarification

v3.8.0 treats envelope streams as the canonical API for lifecycle, diagnostics, and continuity.
DTO-only streams remain data-only convenience APIs and are not continuity-aware.

Clarified behavior:

- malformed JSON / DTO decode failure is represented as `MessageRejected` on envelope streams
- non-target / unknown channel messages are not emitted as target data
- non-target / unknown channel messages do not fault the stream
- non-target / unknown channel messages are observable as `NonTargetMessageIgnored` diagnostics on envelope streams
- DTO-only streams do not express diagnostics or lifecycle events
- reconnect / resubscribe / auth replay / continuity loss order is fixed in the v3.8 plan

## Secret-Free Diagnostics

Realtime diagnostics remain secret-free.
Diagnostic events, exceptions, evidence, logs, stdout, and stderr must not include:

- API key
- API secret
- signature
- Authorization value
- private auth payload
- raw credential profile
- raw credential file path

`NonTargetMessageIgnored` diagnostics may include narrow metadata such as the received channel name and payload length.
They must not include raw payloads or credentials.

## Roadmap Handoff

v3.8.0 does not try to close every future gap.
It classifies gaps so that v3.9 can close the realtime foundation and v4 can start stable baseline work.

Handoff:

- v3.9.0: realtime verification / release close
- v4.x: stable baseline / maintenance / release hardening
- v5.x: Exchange I/O semantics foundation
- v6.x: new venue public read MVP
- v7.0.0+: Unified, only if meaning is defensible

## Non-Scope

v3.8.0 does not include:

- new realtime channel
- Binance realtime
- venue-wide realtime abstraction
- Unified realtime abstraction
- board / account / position / order state reconstruction
- HTTP + realtime state coordination
- Gateway / Platform behavior
- simulation framework
- state-changing operation
- core / venue package Rx dependency
- `ExchangeApi.Optional.Reactive` public API expansion
- `ExchangeApi.Optional.Testing` simulation / Gateway / Platform / Strategy testing expansion
- HTTP contract / consumer verification catch-up
- CTradeBot-specific integration path
- broader consumer verification framework

## Migration

No migration is required for existing HTTP users, DTO-only realtime users, envelope realtime users, optional logging users, optional testing users, or optional reactive users.

Consumers that need lifecycle, diagnostics, or continuity information should use envelope streams rather than DTO-only streams.
