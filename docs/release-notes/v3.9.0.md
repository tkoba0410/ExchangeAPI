# Release Notes v3.9.0

## Highlights

- Closed the v3 Realtime API foundation track.
- Clarified documentation ownership for bitFlyer Realtime contracts, diagnostics, verification policy, and runbooks.
- Refined public, private, and resilience realtime live verification runbooks for v3.9 close.
- Strengthened local and GitHub Packages consumer smoke coverage to include both venue aggregate packages and all current optional packages.
- Classified v3 realtime gaps for v4 stable baseline, v5 semantics, v6 new venue, and v7+ Unified handoff.

## Compatibility

- Existing HTTP endpoint contracts are unchanged.
- Existing DTO-only realtime APIs are unchanged.
- Existing stream envelope APIs are unchanged.
- Existing optional credentials, logging, testing, and reactive APIs are unchanged.
- Core and venue packages still expose `IAsyncEnumerable<T>` as the primary realtime API.
- `System.Reactive` remains limited to `ExchangeApi.Optional.Reactive`.

## Realtime Foundation Close

v3.9.0 is not a feature expansion release.
It closes the v3 realtime foundation by aligning documentation, runbooks, package smoke, and release verification.

Document ownership:

- `docs/realtime-bitflyer.md`: bitFlyer stream / channel / DTO contract
- `docs/realtime-diagnostics.md`: diagnostic event vocabulary / raw frame logging / secret-free observability
- `docs/verification.md`: verification policy / release gate / runbook references
- `verification/`: public / private / resilience live verification runbooks

## Consumer Smoke

v3.9.0 consumer smoke verifies:

- `ExchangeApi.Exchanges.Bitflyer`
- `ExchangeApi.Exchanges.Binance`
- `ExchangeApi.Optional.Credentials`
- `ExchangeApi.Optional.Logging`
- `ExchangeApi.Optional.Testing`
- `ExchangeApi.Optional.Reactive`

The smoke checks do not connect to live exchange APIs.
They verify restore / build / run from local feed and GitHub Packages feed, and confirm smoke output is secret-free.

## Handoff

v4:

- stable baseline / maintenance / release hardening
- HTTP contract / consumer verification catch-up
- ExchangeAPI-wide docs / tests / scripts / package / smoke hardening
- possible automated secret scan / evidence hardening

v5:

- Exchange I/O semantics foundation

v6:

- new venue public read MVP

v7+:

- Unified, only if meaning is defensible

ExchangeAPI continues to avoid state reconstruction, Gateway / Platform behavior, ledger, position, and allocation responsibilities.

## Non-Scope

v3.9.0 does not include:

- new realtime channel
- new public API sugar
- Binance realtime
- venue-wide realtime abstraction
- Unified realtime abstraction
- state reconstruction
- Gateway / Platform behavior
- simulation framework
- HTTP contract / consumer verification catch-up
- v4 stable baseline implementation
- v5 Exchange I/O semantics foundation
- v6 new venue onboarding

## Migration

No migration is required for existing HTTP users, DTO-only realtime users, envelope realtime users, optional logging users, optional testing users, or optional reactive users.

## Safety

- Live tests skip safely without opt-in.
- Actual live realtime verification remains opt-in only.
- Default library usage does not create file logs or evidence.
- Realtime diagnostic events are secret-free.
- API keys, API secrets, signatures, Authorization values, private auth payloads, raw credential profiles, and GitHub Packages tokens must not appear in evidence, logs, results, exceptions, stdout, or stderr.
